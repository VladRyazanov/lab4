# Отчет о тестировании

## 1. Цели и задачи тестирования
**Цель:** Проверка корректности вычисления площади и периметра геометрических фигур (круга и квадрата), а также проверка устойчивости функций к некорректным входным данным.
**Задачи:**
* Составить набор ручных тест-кейсов, покрывающих позитивные, граничные и негативные сценарии.
* Реализовать автоматизированные модульные (unit) тесты с использованием стандартной библиотеки `unittest`.
* Проверить корректность обработки некорректных и граничных входных данных (отрицательных значений и нечисловых типов).

## 2. Описание тестируемого продукта
Продукт представляет собой библиотеку на языке Python для расчета геометрических параметров плоских фигур.

## 3. Область тестирования
Тестированию подлежат следующие модули и функции:
* Модуль `circle.py`:
  * `area(r)` — вычисление площади круга ($\pi r^2$).
  * `perimeter(r)` — вычисление длины окружности ($2 \pi r$).
* Модуль `square.py`:
  * `area(a)` — вычисление площади квадрата ($a^2$).
  * `perimeter(a)` — вычисление периметра квадрата ($4a$).

## 4. Стратегия тестирования
Используется **функциональное тестирование** методом «белого ящика» (модульное тестирование). 
Применяемые техники тест-дизайна:
* **Эквивалентное разделение:** проверка стандартных целых и дробных положительных чисел.
* **Анализ граничных значений:** проверка нулевого значения (`0`) и больших чисел.
* **Негативное тестирование (предугадывание ошибок):** передача отрицательных чисел и некорректных типов данных (строк).

1. Покрытие всех публичных функций модулей `circle.py` и `square.py` модульными тестами.
2. 100% прохождение позитивных и граничных тест-кейсов.
3. Отсутствие критических логических ошибок при работе с валидными данными.

**Пояснение по результатам:**
Все позитивные и граничные тесты (с целыми, дробными числами и нулем) пройдены успешно — математические формулы реализованы верно. 
Провалены 5 негативных тест-кейсов (`TC-04`, `TC-09`, `TC-14`, `TC-18`, `TC-19`). Причина: в коде отсутствуют проверки входных аргументов. Из-за этого функции принимают отрицательные значения, а `square.perimeter("4")` вместо ошибки умножает строку на число и возвращает `'4444'`. Для устранения дефектов необходимо добавить валидацию типов и значений (`if r < 0: raise ValueError(...)`).
